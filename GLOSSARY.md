# Glossary

Domain words used in smallaxe code, tests, and docs. Use these names; do not introduce synonyms.

| Term | Meaning | In code |
|---|---|---|
| **Algorithm** | One of the learning methods smallaxe can train: `random_forest`, `xgboost`, `lightgbm`, `catboost`. An algorithm is described by a declarative record (its param table, Spark estimator and model classes per task, column names, task-fixed params, importance accessor, dependency) plus at most two code hooks (`prepare`, `fit_context`). | `smallaxe/training/algorithm.py` defines `Algorithm`; each algorithm file exports one `ALGORITHM` constant; `algorithm.get(name)` / `algorithm.names()` are the registry. |
| **Param** | One row of an algorithm's strict parameter table: smallaxe name, description, default, Spark estimator name, optional setter, and the tasks it applies to. Users may set only listed params. | `Param` in `algorithm.py`. |
| **Model** | A trainable object with `fit` / `predict` / `save` / `load` / `clone`, bound to one algorithm and one task. Regressors and classifiers are the two kinds. | `Model`, `Regressor`, `Classifier` in `smallaxe/training/base.py`, exported by `smallaxe.training`; `BaseModel` / `BaseRegressor` / `BaseClassifier` are their implementation classes. |
| **Task** | What the label represents: `simple_regression`, `binary`, or `multiclass`. Determines the estimator class, task-fixed params, metrics, and whether `predict_proba` exists. | `REGRESSION_TASKS` / `CLASSIFICATION_TASKS` / `ALL_TASKS` in `smallaxe/training/algorithm.py`, defined there only; persisted in `metadata.json` as `task`. |
| **Factory** | The documented way to get a model: `regressors.xgboost(...)`, `classifiers.catboost(task=...)`, one module-level function per algorithm, plus `load`, `algorithms` and `available_models`. A factory returns a plain `Regressor` / `Classifier`; the factory functions are the only factories, and each documents its algorithm's whole param table. | `smallaxe/training/regressors.py`, `classifiers.py`. |
| **Pipeline** | Ordered preprocessing steps followed by at most one model, trained, applied and saved as one unit. It owns the model's **feature columns**: `numerical_cols` plus the Encoder's `output_cols`; unlisted columns never reach the model. | `smallaxe/pipeline/pipeline.py`. |
| **Step** | One stage of a pipeline: `Imputer`, `Scaler`, `Encoder`, or a model. Its **kind** (`imputer`, `scaler`, `encoder`, `model`) is decided with `isinstance`, never by class name, and is the kind its own artifact records. Other objects work as duck-typed steps but cannot be saved. A step that receives no columns is **skipped**: unfitted, passed through, saved as skipped. | `smallaxe/preprocessing/`, `_step_kind` in `smallaxe/pipeline/pipeline.py`. |
| **Validation** | How `fit` estimates generalisation: `none`, `train_test`, or `kfold`. A row's split or fold is a hash of its content (or `fold_key`) and the seed, independent of the label, so every class splits in the same proportion in expectation. A `Pipeline` passes the same options to its model step, which validates on the preprocessed frame (preprocessing was fitted on every row). | `ValidationMixin`, `_split_hash`; `Pipeline.fit(validation=...)`, `Pipeline.validation_scores`. |
| **Artifact** | A saved directory: the Spark model (if any) plus `metadata.json`, written last. Its header (`format_version`, `kind`, `smallaxe_version`) says what it is and which format it uses; kinds are `model`, `pipeline`, `imputer`, `scaler`, `encoder`. A pipeline artifact holds each saved step's own artifact under `steps/<index>_<name>/`; nothing is pickled. Model artifacts written by 0.10 and earlier have no header (0.8.x ones record their class name, 0.9 and 0.10 ones `algorithm` and `task`) and still load; every 1.x artifact loads in every later 1.x release. | `smallaxe/_artifact.py`, `PersistenceMixin.save`, `Model.load` / `smallaxe.load_model`, `Pipeline.load` / `smallaxe.load_pipeline`, `smallaxe.load` (any kind), `smallaxe/_fs.py`. |
| **Public API** | What 1.x keeps compatible: the names in a public module's `__all__` (no path part starts with `_`), their documented arguments, and the artifact formats. The implementation classes (`BaseModel`, `BaseRegressor`, `BaseClassifier`, the mixins) are listed in `__all__` but are not part of it; their members are public through `Model`. Changes follow semantic versioning; removals are deprecated for at least one minor release first. | `__all__` in every module; `tests/test_public_api.py` pins it. |
